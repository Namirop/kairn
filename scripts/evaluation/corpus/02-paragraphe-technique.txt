Chaque instruction d'un Dockerfile crée une couche, et le cache s'invalide en cascade : dès qu'une couche change, toutes celles qui suivent sont reconstruites. D'où l'ordre habituel, copier le manifeste de dépendances et lancer l'installation avant de copier le reste du code, parce que le code change à chaque commit et pas les dépendances. COPY se contente de copier des fichiers du contexte de build ; ADD y ajoute la décompression d'archives et le téléchargement d'URL, deux comportements implicites qui rendent le build moins prévisible. Le build multi-étapes, lui, compile dans une image outillée et ne copie que le résultat dans une image finale minimale, ce qui évite de livrer le compilateur avec l'application.
